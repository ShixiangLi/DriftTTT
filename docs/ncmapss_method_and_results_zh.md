# DriftTTT：面向 N-CMAPSS 的 RUL 预测框架与实验结果

## 1. 项目目标

本项目面向航空发动机剩余使用寿命（RUL）预测。输入是发动机运行条件和传感器时序，模型输出窗口末端对应的 RUL。

标准 Attention 能建模长序列关系，但推理时参数固定；标准 TTT Layer 可以利用当前序列进行无标签的内部更新，但它的自监督重构任务不一定与 RUL 预测完全一致。基于这两个问题，项目形成了两项核心改进：

1. **TTT-MoE**：从模型结构上同时建模短期波动和长期退化趋势。
2. **CB-DTS**：从训练目标上增加按飞行 cycle 均衡的 RUL 轨迹监督，使 TTT 表征更贴近下游 RUL 任务。

完整方法由 **Transformer 主干 + TTT-MoE + CB-DTS** 组成。CB-DTS 只在训练时生效，因此完整方法与原始 TTT-MoE 的参数量和推理开销相同。

## 2. 整体框架

模型处理流程如下：

```text
运行条件 W + 传感器 X_s
          ↓
  标准化与滑动窗口切分
          ↓
      线性特征投影
          ↓
Transformer Block × 4
  ├─ Attention（基线）
  ├─ 标准 TTT Layer（基线）
  └─ TTT-MoE（结构创新）
          ↓
     共享 RUL 回归头
          ↓
训练：端点损失 + CB-DTS 轨迹损失
测试：仅输出窗口末端 RUL
```

数据按发动机 unit 划分训练集和验证集，官方 test unit 只用于最终评估。标准化统计量只在训练 unit 上拟合，窗口不会跨越 unit 边界。

正式实验不把绝对 cycle 作为模型输入，即 `include_cycle=false`。原始整数 cycle ID 仍作为元数据保留，用于 TTT-MoE 的物理边界划分和 CB-DTS 的轨迹标签恢复，不会作为额外特征输入模型。

## 3. 创新一：多尺度 TTT-MoE

### 3.1 设计动机

工业时序同时包含两类信息：

- 单次飞行内部的快速变化和局部扰动；
- 跨飞行 cycle 的缓慢退化趋势。

单一 TTT 专家使用同一更新尺度处理所有变化，容易在短期噪声和长期趋势之间折中。TTT-MoE 在固定的 TTT 隐藏维度预算内划分短、长两个专家，使两种时间尺度分别建模。

### 3.2 核心步骤

**短期专家**直接处理原始时间步，负责高频变化。当前配置将约 70% 的隐藏维度分给短期专家，并以较快的 TTT 内部学习率更新。

**长期专家**先把连续观测划分为固定长度的 segment，再对 segment 均值执行较慢的 TTT 更新。segment 在真实 flight cycle 边界处重新开始，避免把两个物理 cycle 错误合并。

模型根据当前 query 学习门控权重，将两个专家的输出组合为：

\[
h_{\mathrm{mix}} = h_q + g\,r_{\mathrm{short}} + (1-g)\,r_{\mathrm{long}}.
\]

其中，\(r_{\mathrm{short}}\) 和 \(r_{\mathrm{long}}\) 分别是短、长期专家的自适应残差，\(g\) 是数据驱动的门控。长期残差在有效序列上进行中心化，避免长期专家破坏 query 路径中的绝对健康水平。

### 3.3 方法特点

- 两个专家共享一份固定隐藏维度预算，不是简单扩大模型。
- TTT 内部更新仍使用无 RUL 标签的重构任务。
- cycle ID 只用于划分长期 segment，不作为模型数值特征。
- 测试时可以基于当前输入完成无标签适应，不需要真实 RUL。

## 4. 创新二：CB-DTS 训练算法

CB-DTS 的全称是 **Cycle-Balanced Dense Trajectory Supervision**，即按 cycle 均衡的稠密轨迹监督。

### 4.1 设计动机

原始训练只监督每个窗口最后一个时间点：

\[
L_{\mathrm{end}}=(\hat y_T-y_T)^2.
\]

这与 TTT 的序列级自监督更新存在粒度差异：TTT 会更新整段序列状态，但 RUL 任务只在末端提供一个监督信号。CB-DTS 利用 N-CMAPSS 的 cycle 定义，为窗口内所有有效位置恢复 RUL 轨迹，使整段 TTT 表征都接收到与 RUL 相关的训练信号。

### 4.2 稠密标签恢复

设窗口末端的已知训练标签为 \(y_T\)，末端 cycle 为 \(c_T\)，位置 \(t\) 的 cycle 为 \(c_t\)，RUL 上限为 \(R\)。归一化后的轨迹标签为：

\[
y_t=\min\left(1,\ y_T+\frac{c_T-c_t}{R}\right).
\]

这里的 \(y_T\) 来自 N-CMAPSS 开发集的 `Y_dev`。恢复过程只发生在训练阶段，不需要伪标签模型。

### 4.3 Cycle 均衡

N-CMAPSS 中不同 flight cycle 包含的采样点数量不同。如果直接对所有时间点求平均，持续时间较长的 flight 会获得更大权重。CB-DTS 采用两级平均：

1. 在每个 cycle 内平均时间点误差；
2. 再对窗口中的 cycle 等权平均。

记第 \(c\) 个 cycle 的有效位置集合为 \(S_c\)，轨迹损失为：

\[
L_{\mathrm{CB}}
=\frac{1}{|\mathcal C|}
\sum_{c\in\mathcal C}
\frac{1}{|S_c|}
\sum_{t\in S_c}(\hat y_t-y_t)^2.
\]

最终训练目标为：

\[
L=\frac{L_{\mathrm{end}}+\lambda L_{\mathrm{CB}}}{1+\lambda},
\qquad \lambda=0.5.
\]

### 4.4 训练与测试的区别

- 训练时，共享回归头输出整段 RUL 序列，同时计算端点损失和 CB-DTS。
- 验证和测试时，只使用窗口末端预测，检查点也按端点验证 MSE 选择。
- 测试 RUL 标签只用于离线计算 RMSE、MAE 和 NASA Score，不输入模型。
- CB-DTS 不增加模型参数，也不增加部署阶段的计算量。

因此，CB-DTS 更准确的定位是**面向 TTT 表征的任务对齐辅助训练目标**，不是测试时使用标签的在线学习，也不是标准的元学习算法。

## 5. 实验设计

### 5.1 数据与方法

实验使用 9 个可用 N-CMAPSS 子集：

`DS01-005`、`DS02-006`、`DS03-012`、`DS04`、`DS05`、`DS06`、`DS07`、`DS08a-009`、`DS08c-008`。

对比四种方法：

| 方法 | 说明 |
|---|---|
| Attention | 标准多头自注意力基线 |
| TTT-MLP | 标准 TTT Layer 基线 |
| TTT-MoE | 只使用多尺度专家结构，训练仍为端点监督 |
| CB-DTS | TTT-MoE 加 CB-DTS，代表完整方法 |

每种方法使用 5 个固定 seed：`7、42、123、202、3407`，总计：

\[
9\ \text{子集}\times4\ \text{方法}\times5\ \text{seed}=180\ \text{次实验}.
\]

### 5.2 主要配置

| 配置项 | 数值 |
|---|---:|
| 输入特征 | `W + X_s` |
| `include_cycle` | `false` |
| 窗口长度 | 512 |
| 训练/评估 stride | 512 / 512 |
| 下采样倍率 | 10 |
| RUL cap | 125 |
| Transformer 层数 | 4 |
| 隐藏维度 | 128 |
| 最大 epoch | 60 |
| Early stopping patience | 12 |
| `split_seed` | 42 |
| CB-DTS 权重 | 0.5 |
| 确定性模式 | `true`（best effort） |

训练、验证和测试都不使用 partial window。所有方法共享相同的数据划分、主干规模、优化器、训练预算和验证选模规则，保证比较公平。

正式批次位于：`outputs/batches/20260810_151547`。

## 6. 实验结果

### 6.1 五 seed、九子集总体结果

下表是 45 个“子集 × seed”实验单元的宏平均结果，数值越低越好。

| 方法 | 平均 RMSE | 平均 MAE | 平均 NASA Score |
|---|---:|---:|---:|
| **CB-DTS（完整方法）** | **10.2776** | **7.4660** | 11722.45 |
| TTT-MoE | 10.3757 | 7.5280 | 11756.86 |
| TTT-MLP | 10.4508 | 7.5693 | **11083.50** |
| Attention | 10.8207 | 7.9638 | 12558.51 |

从 RMSE 看：

- 完整方法相对 Attention 降低约 **5.02%**，45 个配对单元中取得 **33 胜、12 负**。
- 完整方法相对标准 TTT Layer 降低约 **1.66%**。
- 完整方法相对原始 TTT-MoE 降低约 **0.95%**，取得 **27 胜、18 负**。

这说明完整方法已经稳定优于 Attention，并在五 seed 总体平均上取得最佳 RMSE 和 MAE；但相对 TTT-MoE 的优势较小，暂不能表述为在所有 seed 和子集上稳定全面领先。

### 6.2 各子集平均 RMSE

| 子集 | Attention | TTT-MLP | TTT-MoE | CB-DTS |
|---|---:|---:|---:|---:|
| DS01-005 | **8.3530** | 8.4895 | 8.7966 | 9.4808 |
| DS02-006 | 7.6984 | 7.3714 | 7.5592 | **7.1709** |
| DS03-012 | 9.4845 | 9.9825 | 9.7624 | **8.9196** |
| DS04 | 15.0129 | 14.0142 | 13.7869 | **13.7321** |
| DS05 | 11.3208 | 10.4781 | 9.9606 | **9.4914** |
| DS06 | 10.1572 | 9.7451 | 9.8088 | **9.2012** |
| DS07 | 13.3954 | 13.0892 | **12.0998** | 12.9172 |
| DS08a-009 | 13.7542 | **12.5695** | 13.5345 | 13.4726 |
| DS08c-008 | 8.2099 | 8.3175 | **8.0730** | 8.1129 |

CB-DTS 在 `DS02-006`、`DS03-012`、`DS04`、`DS05`、`DS06` 上取得最佳平均 RMSE，共 **5/9** 个子集。主要短板是 `DS01-005` 和 `DS07`，表明轨迹辅助监督的收益仍受子集退化模式和开发/测试 unit 分布差异影响。

### 6.3 Seed 稳定性

| Seed | Attention | TTT-MLP | TTT-MoE | CB-DTS | 最优方法 |

CB-DTS 在 seed 42 和 123 上取得四种方法中的最佳结果；相对 TTT-MoE，则在 42、123、202、3407 四个 seed 上更优。

## 7. 结论与当前阶段定位

当前项目的两项创新分别解决不同层面的问题：

- **TTT-MoE**解决工业时序中短期扰动与长期退化并存的问题，是结构层创新。
- **CB-DTS**缓解 TTT 序列级自监督更新与端点 RUL 监督之间的不匹配，是训练算法创新。

二者组合后，在不增加 CB-DTS 推理成本的前提下，九子集五 seed 的平均 RMSE 和 MAE 均达到当前四种方法中的最佳水平，并稳定超过标准 Attention。

同时需要保留客观结论：CB-DTS 相对原始 TTT-MoE 的平均 RMSE 提升约 0.95%，在不同子集上仍有异质性。当前版本适合作为一个已完成的阶段性里程碑，后续如继续研究，应优先解释 `DS01-005`、`DS07` 的分布差异，而不是继续堆叠额外模块或训练技巧。

## 8. 复现实验

正式实验前需确认 N-CMAPSS 配置使用：

```yaml
data:
  options:
    include_cycle: false
training:
  deterministic: true
```

然后运行：

```bash
bash run_experiments.sh \
  --dataset ncmapss \
  --subsets all \
  --mixers all \
  --seeds 7,42,123,202,3407 \
  --gpus 0,1,2,3,4,5,6,7 \
  --jobs-per-gpu 2
```

其中 `--mixers all` 会运行 Attention、TTT-MLP、TTT-MoE 和 CB-DTS。`cb_dts` 在批处理入口中自动映射到 `ttt_multiscale_moe`，并启用权重为 0.5 的 CB-DTS 训练损失。
